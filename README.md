# Tying the Knot — poster figures

Python code for Eric Moon's wedding-ring mathematics poster, with transparent PNG figures and editable SVG versions of the two-dimensional drawings. One script corresponds to each poster block that contains mathematical figures.

## Folder contents

- **`code/`** — eight commented Python scripts, `requirements.txt`, and the required `geometry/` data. Keep this folder together: the data stores curve coordinates, diagram outlines, text outlines, tree placement and material settings used by the scripts.
- **`figures/`** — 36 mathematical PNG figures, SVG versions where applicable, and the original transparent ring photograph. The photograph is an input asset, not generated by the scripts. The SLU logo is excluded.
- **`README.md`** — these instructions.

There are no comparison sheets, verification reports, backup ZIPs or intermediate calculation files. Checks built into the figure scripts print their results without creating additional report files.

## Install

Use Python 3.12. Open a terminal in the extracted `Wedding_Ring_Figures` folder, then install the dependencies:

```sh
python -m pip install -r code/requirements.txt
```

On systems where Python is called `python3`, use `python3` in place of `python`.

CairoSVG requires the system Cairo library. If it reports a missing Cairo library, install Cairo for your operating system using the [CairoSVG installation instructions](https://cairosvg.org/documentation/). The 3D script also requires an OpenGL 3.3 context: it tries offscreen EGL first and then the platform's default context. The original rendering environment was Linux with Mesa software rendering. No Manim or LaTeX installation is needed.

## Generate the figures

Run only the script for the block you want, or run all eight commands. Each script locates its data relative to its own file and saves into the project's `figures/` folder. Existing files with the same names are overwritten.

```sh
python code/01_knots_and_links.py
python code/02_reidemeister_moves.py
python code/03_modeling_ring.py
python code/04_candidate_links.py
python code/05_linking_number.py
python code/06_fox_3_colorings.py
python code/07_jones_polynomial.py
python code/08_diagram_equivalence.py
```

To generate the updated ring model and its construction stages, run:

```sh
python code/verify_geometry.py
python code/render_construction.py
```

The updated model is evaluated by `refined_points` in
`code/geometry.py`. It adds small variations to the faces and
rims while retaining the two defining link curves.

The new renderer saves `03-compact-ring.png` and
`06-compact-with-curves.png`. These are the updated model images;
`03_modeling_ring.py` alone generates the earlier model.

See `Construction.pdf` for the mathematical construction and
`Construction.tex` for its editable source.

The 3D ring script is the most demanding; it renders a large intermediate framebuffer before exporting the PNGs.

Each script lists its output filenames at the beginning. Comments before the individual figure calls describe what is being drawn. The determinant block uses LaTeX matrices and tables, so it needs no separate image-generating script.

## How the drawings are produced

The fixed diagrams use explicit vector outlines stored in `code/geometry/`. These outlines include the curves, crossing gaps, dots, arrows and lettering. The scripts assemble SVG drawings from those coordinates, then render transparent PNGs; they do not read the poster PNGs to create the mathematical illustrations.

The 3D models use parametric surfaces, gold materials and depth-tested red/blue boundary curves. The deformation script interpolates and smooths the stored curve geometry. The Jones script computes each state's smoothings and loop count, preserving the tree's layout and labels. It also checks the bracket simplification and all 16 rendered final loop counts.
